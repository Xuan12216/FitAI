# FitAI 1.2 Code Review 與驗收

本次由實作者檢查修改內容與回歸測試，沒有獨立外部審查者。

## 最終範圍

- 參考 GemAgora 加入字體 85%／100%／115%／130% 預設檔、5% 刻度滑桿、預覽與保存。全 App 的縮放乘上系統字體比例。
- 設定新增獨立「備份」分頁，集中手動 JSON 匯出／還原與檔案方式的 Google Drive 自動備份。
- 自動備份可選每小時、6 小時、每天、每週，或自訂 15 分鐘至 30 天；可限制非計量網路，並提供立即備份、還原預覽與本機快照。
- 依使用者最後指示，取消 LINE 式 Google 帳號登入／OAuth 串接，未加入 Google 登入 SDK、憑證或 Drive REST API，不需要設定 Google Cloud。
- 檔案方式採 Android Storage Access Framework 的指定 Drive 文件授權；首次選檔前不啟用排程。雲端同步由 Google Drive App 管理，畫面只將成功關閉文件串流稱為「交付 Drive」，不將它誤報成已確認伺服器同步。
- 備份內容沿用目前紀錄格式：餐點、常用標記、體重、課表與組數；不含聊天、個人設定與模型。

| P1 | 無效備份或產生失敗可能先截斷原備份檔 | 完整匯出、大小檢查、格式驗證與本機 AtomicFile 快照完成後，才開啟遠端串流 |
| P2 | 暫停、解除連結與傳輸並行 | 以共用 Mutex 序列化傳輸和設定變動；解除時停止唯一工作並釋放文件授權，保留遠端檔案 |

## 驗證

- Release 建置、Release lint 與 git diff --check 通過。Lint 無 errors，保留依賴升級／舊介面等非阻擋提示。
- 45 項 JVM 測試通過，包含字級保存、無效比例處理、備份間隔驗證、斷開連結、授權失效與舊回報隔離。
- 13 項 Android 測試通過：5 項摺疊版面、2 項 WorkManager 排程、6 項紀錄完整性。排程驗證更新維持同一工作、暫停取消、立即備份去重及未設定時不執行。
- 手機實測選取 130% 後套用全域字體，重啟後仍保存；驗收後還原 100%。
- 手機使用相同本機簽章覆蓋安裝 Release 1.2（versionCode 3），未解除安裝或清除原有資料。

## 外部驗收邊界

依使用者取消 LINE 式串接的指示，未進行 Google Cloud 設定或帳號式 OAuth 連結。最後實機畫面顯示檔案式備份已連結 FitAI-auto-backup.json、每日一次，且最近交付 Drive 為 10/23 13:13；保留手機現有設定，沒有代為更換文件、觸發新備份或還原使用者紀錄。實際 Drive 伺服器同步與雲端還原未進行端到端驗證，交付時間僅表示文件供應器接受寫入。排程與資料完整性以隔離模擬器及測試資料驗證。

Google Drive 文件供應器的寫入與雲端同步並非 App 可控制的原子交易；若傳輸中斷，遠端檔案可能不完整。App 保留已驗證的本機快照，還原也會先解析整份檔案、顯示筆數並確認，失敗時不修改現有紀錄。
