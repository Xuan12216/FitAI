# FitAI 1.3 營養資料輔助與 Code Review

本次由實作者檢查程式與回歸測試，沒有獨立外部審查者。

## 實作範圍

- 新增／編輯餐點與拍照分析提供「營養資料輔助」開關，預設開啟。以食藥署食品營養成分資料集輔助本地模型，不是 Google 搜尋或雲端模型評估。
- 首次點評估時從官方 HTTPS 下載約 4.7 MB ZIP，串流解析約 138 MB 原始 JSON，只保留完整且合理的熱量、蛋白質、碳水與脂肪。無需 API 金鑰，不上傳餐點查詢、照片或個人資料。
- 原始資料不打包在 APK，精簡快取保存在 App 快取目錄，7 天後嘗試更新；更新失敗可使用既有資料，來源顯示實際下載時間。系統清除快取後會重新下載。
- 支援名稱／俗名及更具體樣品的比對。「牛肉」等一般肉類查詢會從肉類資料找相關部位，排除牛奶、牛肉醬、餡餅與蝸牛肉；「牛肉麵」不會反向套用單一牛肉數值。優先完整名稱與已公布平均值，否則提供最多 5 筆不同候選樣品。
- 送入模型前再估算完整提示詞長度，保留系統開銷、50% 輸入估算餘裕及至少四分之一上下文／256 tokens 回答空間，容量不足就減少候選；低於 1024 的上下文不加入參考。這是保守估算，不是實際 tokenizer 計數。
- 每筆參考只傳樣品 ID、名稱、精簡描述及每 100 克數值，明確要求模型選擇候選，不把候選相加；部位、料理方式及份量不明時應說明假設。
- 明確輸入 g／克／kg／公斤時，模型只選樣品，程式依原始資料換算數值及說明，保留巨量營養素小數。未提供有效樣品 ID 時暫用第一筆並明示假設；來源明細保存並標記使用樣品。1 份／1 碗仍由模型估算，營養值不應因增肌或減脂目標而改變。
- 只有成功完成參考輔助估算後，結果才附上地球圖示與「資料庫參考」標示，區分聯網取得／快取；可點開查看實際傳入的候選、原始數值、下載時間、官方連結及資料授權。
- 來源隨餐點儲存與複製，編輯名稱／份量會清除不適用的來源。手動新增後使用 AI 的餐點也正確保存 AI 估算狀態。
- Room 4→5 新增可空來源欄位；備份格式升為 2，仍可匯入版本 1，版本 2 保留來源並驗證內容。舊版 App 不支援新備份格式。
- 查無資料、網路錯誤或 20 秒查詢逾時會回退本地估算，顯示原因；使用者取消會傳遞取消，不假裝成已取得來源。

## Review 修正

| 等級 | 發現 | 處理 |
| --- | --- | --- |
| P1 | 官方舊網址 301 導向 HTTP，使實機無法取得資料 | 改用官方新的直接 HTTPS 下載端點，保持禁止降級／任意重新導向，補上真實下載與跨實例快取測試 |
| P1 | 實機模型將蛋白質／脂肪克數加進熱量算式，且因增肌目標偏選高脂肪樣品 | 加入樣品 ID、禁止目標影響數值／選樣；明確重量由程式換算，取代模型算式並保存使用樣品 |
| P1 | 新增來源欄位後可能在資料升級／備份還原時遺失來源 | Room 無損 migration、新舊備份相容與來源往返測試 |
| P2 | 廣義牛肉查詢可能優先選中加工食品或其他類別 | 一般肉類查詢先限定肉類，再排序部位與樣品 |
| P2 | 直接塞全部結果可能耗盡上下文，或將多筆候選相加 | 精簡且有上限的候選、完整提示詞預算、輸出預留、候選選擇指示 |
| P2 | 網路可用或模型自稱搜尋過就被標成網路評估 | 來源由查詢層產生，只保存實際傳入且完成估算的資料；查詢失敗無來源標示 |
| P2 | 缺值被當成 0、下載過大或原始 JSON 大量配置造成記憶體壓力 | 缺少任一主要營養值就排除，檢查有限非負值、壓縮／解壓／筆數限制，串流解析、AtomicFile 快取 |
| P2 | 估算中改名稱／份量造成來源與最後餐點不符 | 推論期間停用名稱／份量與模板輸入，保存成功後才更新來源 |

## 限制

這版不是通用網路搜尋，品牌、餐廳複合餐點或資料庫未收錄名稱可能查無資料。參考資料可以減少無依據推測，但無法保證模型選對樣品，或在未指定克數時正確估算份量；最終仍保留手動校正。模型容量控制為估算，非實際 tokenizer 的硬性保證。來源不是 Google 認證或營養準確度保證。

官方資料：[食品營養成分資料集](https://data.gov.tw/dataset/8543)，依政府資料開放授權條款第 1 版使用。下載端點為 https://data.fda.gov.tw/data/opendata/export/20/old-json 。
