# 多來源 AI、查詢監測及份量規則：1.3.5（9）

## 結果與規則

- 實作 Google AI、Brave AI、Duck.ai 三個公開頁面來源，不使用私人 API、代理、指紋偽裝或驗證繞過。
- 每次自動估算最多合計三次提問，同次估算各來源最多一次；隨機選擇時排除上一次實際查詢來源，並只保存上次來源名稱供重啟後延續。快取不推進輪替。
- 一般連線錯誤、逾時或不完整回答可改查其他來源。遇到驗證、403／429 或需登入的跳轉時停止整次網路流程，轉台灣資料／本地 Gemma，不以輪替繞過驗證。
- 「再查一次網路 AI」僅追加一次提問，選擇不同於上一筆的來源。失敗不重跑 Gemma，也不覆寫已填入的營養數值。掃描結果重試期間暫停數值編輯與儲存。
- 所有來源提示要求繁體中文。這是模型提示，不宣稱遠端服務必定遵守或原始引用頁也一定是繁體。
- 依使用者後續更正，不再限制中國模型；可使用 Qwen。Brave 的底層模型可能變動，因此顯示「Brave AI」，不假稱已確認每次的模型版本。Duck.ai 從實際回答標頭讀取模型名稱，缺少模型名稱時不採用該回答。
- 本地 Gemma prompt 補上「四項數值必須是使用者份量的總量，不是默認每 100g」；未知一份克重需說明估計。程式仍僅換算可明確對應的重量／份數，不將一份自行變成 100g。未重新下載或切換模型。

## 監測與隱私

`GoogleAiTrafficMonitor` 記錄本次 App 程序的提問、快取、重複請求數、上次來源、耗時、狀態及 HTTP 錯誤碼。只記錄本機統計，不保存或上傳食物名稱、提示、回答內容或網址。

- 共用查詢鎖以 `tryLock` 略過並行重複請求，不排隊補送。
- 本機最近 60 秒累積六次提問時顯示密集提醒，並停止追加自動重試。仍可由使用者明確再查一次，沒有恢復固定 20 秒／30 分鐘冷卻。
- 六次是 App 的保守提醒，不是 Google 或其他服務的公布配額，不能預測或保證避免封鎖。
- UI 每秒刷新本機計數不會發送提問；不統計頁面資源載入、服務內部搜尋次數、其他 App 或整個 IP 的流量。
- `FitAI_Traffic` 及既有 `FitAI_WebAI` 僅輸出來源／計數／階段耗時等狀態，不輸出查詢或回答正文。回答與引用仍依既有餐點來源功能保存，用於使用者查看來源；與監測紀錄不同。

## 來源驗證

裝置：Samsung SM-F9710。獨立套件 `com.xuan.fitai.probe`，未寫入正式 App 餐點或備份設定。

- Brave：一次提問約 **7.168 秒**取得可用四項營養值與來源，來源 URL 可能以純文字呈現；擷取 AI 實際列出的 HTTPS URL，不挪用其他搜尋結果假裝引用。
- Duck.ai：使用者已確認首次條款測試。一次提問約 **15.766 秒**取得可用數值，回答標頭為 **GPT-6 Luna**，包含引用。程式先透過公開 UI 啟用「網頁搜尋」，確認啟用後才送出；不因提示提到「搜尋」就假設已聯網。表單只送出一次。
- `MultiAiLookupTest`：實際來源查詢及三家資料／舊 Google JSON 相容往返共 **2 項通過**。
- Google 的單獨追加提問：這次頁面載入後 25 秒仍沒有 AI 回答，測試斷言失敗。沒有觀察到驗證或封鎖，不能將該失敗解釋為 IP 被鎖，也不把這項測試計為通過。
- 隨後使用自動查詢入口、優先 Google 的實測，約 **4.583 秒**即由 Google 回覆（1 次提問），完整流程測試 **1 項通過**。因此不能把先前單筆逾時解釋為持續封鎖；這一次沒有實際走到下一家，跨來源錯誤備援由可重現的單元測試驗證。
- Perplexity 公開頁面遇到 Cloudflare 安全驗證，未繞過、未加入；Microsoft Copilot 公開入口要求登入，未登入、未加入。Duck.ai 與 Brave 的桌面畫面另附於本目錄。
